# תוכנית – Milestone 3: ניהול ושיתוף בדיחות

> מקורות: `PRD.md` (FR-04, FR-05, Edge Cases), `ARCHITECTURE.md` (§1 סיכון 4, §2.2, §2.5, §2.6), `DESIGN.md` (§1.1, §2.3, §2.5), `style-guide.png` (כפתורי "מחק" ו"ביטול", כרטיס עם "העתקה"/"שיתוף"/פח), `MILESTONES.md`.
> מצב נוכחי (Milestone 2 ✅): `App.tsx` מחזיק `jokes`, טעינה, שגיאה ו-`announcement`; `JokeList` מציג כרטיסים עם טקסט בלבד; `JokeStatus` הוא אזור `role="status"`; אייקונים כ-SVG inline (אין ספריית אייקונים).
> Web APIs: `navigator.clipboard.writeText`, `navigator.share` (MDN), `<dialog>` + `showModal()`. ב-jsdom אין `showModal` (נבדק) — נדרש Stub בבדיקות.

## 1. מטרה והיקף

לכל בדיחה: העתקה, שיתוף (כשנתמך) ומחיקה. במסך הראשי: "ניקוי בדיחות". כל מחיקה דורשת אישור ב-Dialog נגיש. הכל באותו מסך, בזיכרון בלבד.

**בתוך ההיקף:**
- שורת פעולות בכל כרטיס: "העתקה", "שיתוף", כפתור מחיקה (אייקון פח עם שם נגיש).
- כפתור "ניקוי בדיחות" ליד כותרת "רשימת בדיחות".
- רכיב `ConfirmDialog` אחד לשני סוגי המחיקה.
- משוב נגיש להעתקה/שיתוף.
- בדיקות אוטומטיות.

**מחוץ להיקף (לא לממש):**
- תפריט, מסכי אודות/עזרה/הגדרות, כוכב מועדפים, אימוג'י בכרטיסים (מופיעים בתמונות בלבד).
- "ביטול פעולה" (Undo) אחרי מחיקה, Toast נפרד, ספריית אייקונים או ספריית Dialog.
- Offline / PWA (Milestone 4), Deployment (Milestone 5).
- כל אחסון מתמשך (`localStorage` וכו').

## 2. החלטות התנהגות

**שיתוף כשאינו נתמך (PRD השאיר להחלטה בתכנון; ARCHITECTURE §2.6 קבע):** כפתור "שיתוף" מוצג **רק** כש-`typeof navigator.share === 'function'` ו-`window.isSecureContext`. אחרת הכפתור לא מוצג כלל — אין כפתור שבור או מושבת; "העתקה" נשארת זמינה תמיד.
- שיתוף: `navigator.share({ text })` — טקסט הבדיחה בלבד (בלי כתובת וכותרת).
- המשתמש סגר את חלונית השיתוף (`AbortError`) → לא קורה כלום, לא הודעת שגיאה.
- שגיאה אחרת → הכרזה "לא הצלחנו לשתף".

**העתקה:** `navigator.clipboard.writeText(joke.text)` — טקסט הבדיחה הנבחרת בלבד.
- הצלחה: התווית של אותו כפתור מתחלפת ל"הועתק!" למשך כ-2 שניות, והכרזה "הבדיחה הועתקה" באזור ה-`status`.
- כשל או API לא זמין: הכרזה "לא הצלחנו להעתיק" (הכפתור נשאר, כי ייתכן שהבעיה זמנית — למשל הרשאה).

**מחיקת בדיחה בודדת:** לחיצה על הפח → Dialog. אישור → הסרת אותה בדיחה בלבד (לפי `id`), סדר האחרות נשמר. ביטול / Esc → אין שינוי.

**ניקוי בדיחות:** הכפתור מוצג רק כשיש לפחות בדיחה אחת (אין מה לנקות ברשימה ריקה). אישור → `jokes = []`; ביטול → אין שינוי. אחרי ניקוי: הכותרת "רשימת בדיחות" נשארת והרשימה ריקה — בדיוק כמו בפתיחת האפליקציה (בלי טקסט "אין בדיחות" חדש, כי לא הוגדר ב-spec).

**השפעה על בקשות יצירה:** `previousJokes` מחושב מהרשימה הנוכחית, כך שבדיחה שנמחקה לא תישלח כהקשר בבקשה הבאה. אם בקשת יצירה בתהליך בזמן ניקוי — הבדיחה החדשה תתווסף לרשימה הריקה כשתגיע (זה התנהגות סבירה; אין ביטול בקשה).

## 5. רכיבים

**`JokeCard`** (`<li>`): טקסט הבדיחה כמו היום (`<p dir="auto" lang>`), ומתחתיו שורת פעולות. לפי ה-Wireframe ב-RTL: "העתקה" מימין, "שיתוף" אחריה, פח בצד השמאלי. כפתורים משניים קטנים (אייקון + טקסט), שטח לחיצה מינימלי 44×44px, Focus גלוי. ל"העתקה"/"שיתוף" יש טקסט גלוי, אבל כדי שקורא מסך יבחין בין כרטיסים — כל כרטיס מקבל `aria-labelledby`/`aria-describedby` לטקסט הבדיחה (ההחלטה הסופית בבנייה, בדיקה עם קורא מסך).

**`JokeList`:** שורת כותרת — `h2` "רשימת בדיחות" מימין, כפתור "ניקוי בדיחות" (משני, אייקון פח) משמאל, רק כשיש בדיחות. `h2` מקבל `tabIndex={-1}` כדי לשמש יעד Focus אחרי מחיקה.

**`ConfirmDialog`:** `<dialog>` טבעי עם `showModal()`:
- הדפדפן נותן: חסימת שאר הדף (Focus לא יוצא מה-Dialog), Esc לסגירה, ותפקיד `dialog` לקורא מסך.
- `aria-labelledby` לכותרת, `aria-describedby` לתיאור.
- Focus ראשוני על "ביטול" (הבחירה הבטוחה).
- Esc או "ביטול" → `onCancel`; "מחק" → `onConfirm`. לחיצה מחוץ ל-Dialog לא סוגרת (מונע ביטול/אישור בטעות).
- עיצוב: כרטיס לבן, פינות 16px, צל רך, רקע מוחשך (`::backdrop`); "מחק" אדום עם אייקון פח, "ביטול" לבן עם מסגרת — כמו ב-Style Guide.

**ניהול Focus אחרי סגירה:**
- ביטול → חזרה לכפתור שפתח את ה-Dialog (הפח של אותו כרטיס / "ניקוי בדיחות").
- אישור מחיקה / ניקוי → הכפתור שפתח כבר לא קיים, לכן Focus עובר לכותרת "רשימת בדיחות".

**State ב-`App.tsx`:** `pendingDelete: { kind: 'one'; id: string } | { kind: 'all' } | null` + שמירת האלמנט שפתח את ה-Dialog (`useRef`). ההכרזות עוברות דרך `announcement` הקיים ו-`JokeStatus` (אזור `aria-live` אחד לכל המסך).

## 6. בדיקות

**`App.manage.test.tsx`** (`fetch` מדומה ליצירת 2–3 בדיחות, `navigator.clipboard`/`navigator.share` מדומים):
- העתקה → `writeText` נקרא עם טקסט הבדיחה שנבחרה בלבד (לא של אחרת); התווית "הועתק!" + הכרזה.
- העתקה נכשלה / API חסר → "לא הצלחנו להעתיק", בלי קריסה.
- בלי `navigator.share` → אין כפתור "שיתוף" בכלל.
- עם `navigator.share` → הכפתור קיים ונקרא עם `{ text }` של הבדיחה הנכונה.
- שיתוף בוטל (`AbortError`) → אין הודעת שגיאה; שגיאה אחרת → "לא הצלחנו לשתף".
- מחיקה: פח → Dialog עם כותרת; Focus על "ביטול". "ביטול" → אותן בדיחות באותו סדר, Focus חזר לפח. "מחק" → רק הבדיחה האמצעית הוסרה, האחרות בסדר המקורי.
- Esc → כמו ביטול.
- ניקוי: לא מוצג ברשימה ריקה; ביטול → אף בדיחה לא נמחקה; אישור → רשימה ריקה, הכפתור נעלם, Focus על הכותרת.
- אחרי מחיקה — בקשת יצירה הבאה לא שולחת את הבדיחה שנמחקה ב-`previousJokes`.
- אין שימוש ב-`localStorage`/`sessionStorage` (Spy על `Storage.prototype.setItem`).
- עדכון בדיקת ה-Tab של Milestone 1 אם תושפע (ברשימה ריקה היא לא אמורה להשתנות).

**בדיקות ידניות שלי בדפדפן (מול השרת המקומי):**
- העתקה והדבקה בפועל.
- שיתוף: ב-Chrome במחשב ובאמולציית מובייל; בדפדפן בלי תמיכה — הכפתור לא מופיע.
- מעבר מלא במקלדת: Tab לכפתורי הכרטיס, Enter על פח, Tab בתוך ה-Dialog לא יוצא ממנו, Esc, החזרת Focus.
- בדיקת עץ הנגישות (תפקידים ושמות) של ה-Dialog והכפתורים.
- פריסה ברוחב מובייל — שורת הפעולות לא שוברת שורה בצורה מכוערת ואין גלילה אופקית.

**מגבלה ידועה:** אין לי מכשיר iOS/Android אמיתי — שיתוף אמיתי במובייל ייבדק אצלך (ובאופן מלא ב-Milestone 5).

## 7. נגישות וצבעים

- **אדום לכפתור "מחק":** `#EF4444` מה-Style Guide עם טקסט לבן נותן ניגודיות של כ-3.8:1 — פחות מ-4.5:1 הנדרש ב-WCAG AA לטקסט רגיל. אשתמש בגוון כהה יותר `#DC2626` (כ-4.8:1) כטוקן `--color-danger` לכפתור בלבד. יתועד כ-ADR-7 (כמו ADR-4 למסגרת השדה).
- כל כפתור אייקון עם שם נגיש; אייקונים `aria-hidden`.
- הודעות העתקה/שיתוף/מחיקה דרך `aria-live="polite"` הקיים; לא מסתמכים על צבע בלבד.
- `dir="auto"` נשמר לטקסט הבדיחה; שורת הפעולות בעברית RTL.
