# MILESTONES – בדיחה בקליק

מסמך זה מגדיר אבני דרך לפיתוח על בסיס `PRD.md`, `ARCHITECTURE.md` ו-`DESIGN.md`. ה-PRD קובע את היקף המוצר; רכיבים המופיעים בתמונות בלבד ואינם מאושרים ב-PRD אינם נכללים בפיתוח. כל אבן דרך מסתיימת במערכת עובדת ובבדיקות שניתן להציג למשתמש.

## Milestone 1 – בסיס פרויקט ומסך ראשי עובד

**מטרה:** ליצור בסיס פיתוח שניתן להריץ ולבדוק, עם ממשק ראשי תואם לעיצוב ולשפה.

**מה יש לממש:**
- הקמת Git Repository ב-GitHub עם React, TypeScript ו-Vite, מבנה המאפשר Vercel Function בתיקיית `api/`, ופקודות Build ובדיקות בסיסיות.
- מסך ראשי יחיד בעברית ו-RTL עם כותרת "בדיחה בקליק", תיבת נושא שאינה חובה וכפתור "צור בדיחה"; אזור רשימת בדיחות ריק ומוכן להצגת תוכן.
- סגנון הממשק המאושר לפי `DESIGN.md`: Heebo, צבעים, טיפוגרפיה, כפתורים, שדה קלט ו-Responsive; שימוש ברכיבים המאושרים בלבד.
- HTML סמנטי, תווית נגישה לשדה, סדר Tab ו-Focus גלוי כבר מההתחלה.

**תוצר מצופה:** האפליקציה נפתחת מקומית במובייל ובמחשב, מציגה את המסך הראשי ומאפשרת הזנת נושא. יצירת בדיחה עדיין אינה פעילה; אין הצגה של בדיחות דמה כאילו נוצרו ב-AI.

**Definition of Done:**
- הפרויקט קיים ב-GitHub, התקנת התלויות והרצת סביבת הפיתוח מצליחות, ו-`vite build` ובדיקת TypeScript עוברים.
- השדה מקבל טקסט בעברית ובאנגלית, גם כשהוא ריק, והטקסט אינו מתאפס במהלך הקלדה.
- הממשק RTL, ללא גלילה אופקית ברוחב מובייל מקובל, וניתן להגיע לשדה ולכפתור במקלדת עם Focus גלוי.
- לא קיימים Routes, מסכי הגדרות/אודות או פעולות שלא אושרו.

## Milestone 2 – יצירת בדיחה מקצה לקצה

**מטרה:** לאפשר למשתמש ליצור בדיחה אמיתית לפי נושא או ללא נושא, דרך Backend מאובטח.

**מה יש לממש:**
- `POST /api/jokes` כ-Vercel Function ב-Node.js/TypeScript; אימות קלט, בדיקת מתודה וגודל בקשה, טיפול בתשובות שגיאה, Timeout וקריאה ל-OpenAI Responses API עם `gpt-5`.
- שמירת `OPENAI_API_KEY` בצד השרת בלבד; מפתח Development מקומי ב-`.env.local` שאינו מועלה ל-Git; הפרדה בין הוראות השרת לבין תוכן משתמש.
- הנחיות יצירה: בדיחה באורך 1–3 משפטים, נקייה ומתאימה למשפחה; בשפת הנושא או בעברית לנושא ריק.
- חיבור הכפתור ל-API והוספת כל בדיחה חדשה לתחתית הרשימה בזיכרון React בלבד, תוך השארת הנושא בשדה.
- Spinner וההודעה "מכינים לך בדיחה...", השבתת הכפתור בזמן הבקשה, והודעת "לא הצלחנו ליצור בדיחה. נסו שוב." עם "נסו שוב" ששולח מחדש את הבקשה שנכשלה.
- העברת בדיחות קודמות באותו Session לבקשה כדי לצמצם חזרות, בלי הבטחה למניעה מוחלטת.

**תוצר מצופה:** אפשר לייצר מספר בדיחות אמיתיות ברצף; כל אחת נוספת לרשימה, וניתן לנסות שוב אחרי כשל בלי לאבד בדיחות קודמות.

**Definition of Done:**
- בדיחה נוצרת בנושא בעברית, בנושא באנגלית, ועם שדה ריק; בשדה ריק מתקבלת בדיחה כללית בעברית.
- כל תשובה מוצגת כרכיב טקסט ולא כ-HTML לא מהימן; התוכן עומד ככל שניתן בהנחיות אורך והתאמה למשפחה.
- בקשה שנייה מוסיפה פריט לרשימה ואינה מחליפה את הראשון; הנושא נשאר בשדה; רענון מוחק את הרשימה.
- במהלך בקשה יש Spinner, הודעת טעינה וכפתור מושבת; כשל מדומה מציג הודעה וכפתור ניסיון חוזר, ואותו נושא ונתוני בקשה נשלחים שוב.
- בדיקות API של מתודה לא נתמכת, קלט שגוי/גדול, שגיאת ספק ו-Timeout מחזירות תשובות מבוקרות ללא פרטי סוד.
- `OPENAI_API_KEY` אינו נמצא ב-Repository, בקוד Frontend, ב-Build או בבקשות הדפדפן; בדיקת Build עוברת.

## Milestone 3 – ניהול ושיתוף בדיחות

**מטרה:** לאפשר שימוש מעשי בבדיחות שכבר נוצרו בלי שמירה קבועה.

**מה יש לממש:**
- כפתורי "העתקה" ו"שיתוף" לכל בדיחה; שיתוף דרך יכולות המכשיר כאשר נתמכות, וטיפול לא מטעה במצב שבו אינן זמינות.
- מחיקת בדיחה בודדת וניקוי כל הרשימה באמצעות "ניקוי בדיחות" במסך הראשי.
- Dialog אישור נגיש לפני כל מחיקה, עם אפשרויות אישור וביטול; שמירת סדר הפריטים הנותרים.
- מצב רשימה ריקה לאחר ניקוי, בלי להוסיף מסכים או היסטוריה קבועה.

**תוצר מצופה:** המשתמש יכול להעתיק, לשתף, למחוק בדיחה אחת או לנקות את כולן, כאשר מחיקה דורשת אישור.

**Definition of Done:**
- העתקה מעבירה ללוח את טקסט הבדיחה הנבחרת בלבד; השיתוף מפעיל את ממשק המכשיר בסביבה נתמכת, ובסביבה שאינה נתמכת אין פעולה שבורה.
- מחיקת בדיחה אחת לאחר אישור מסירה רק אותה; ביטול משאיר את הרשימה ללא שינוי.
- ניקוי הרשימה לאחר אישור מסיר את כל הבדיחות; ביטול אינו מסיר אף בדיחה.
- Dialog האישור נגיש למקלדת ולקורא מסך, עם Focus מנוהל כראוי.
- כל הפעולות מתבצעות באותו מסך, ללא Database או אחסון מתמשך.

## Milestone 4 – PWA, Offline והתאמה חוצת מכשירים

**מטרה:** לאפשר התקנה ופתיחה חוזרת של האפליקציה גם ללא רשת, בלי להציג יכולת יצירת בדיחות במצב Offline.

**מה יש לממש:**
- `vite-plugin-pwa` ו-Workbox עם Manifest, אייקוני התקנה נדרשים ו-Service Worker המאפשר Precache לנכסי הממשק בלבד.
- זיהוי מצב Offline והודעה בעברית: "אין חיבור לאינטרנט. כדי ליצור בדיחה יש להתחבר לרשת." מניעת בקשות יצירה ללא רשת, וחזרה לשימוש לאחר חידוש החיבור.
- החרגת `/api/jokes` מ-Cache; ללא כפתור התקנה ייעודי.
- התאמות Responsive ל-Mobile/Desktop ולדפדפנים הנתמכים, כולל בדיקות נגישות WCAG 2.2 AA במסך ובמצבי טעינה/שגיאה/מחיקה.

**תוצר מצופה:** לאחר טעינה מוצלחת, האפליקציה ניתנת לפתיחה במצב Offline ולהתקנה בדפדפנים התומכים; יצירת בדיחות פעילה רק עם חיבור לרשת.

**Definition of Done:**
- Manifest תקין, Service Worker נרשם, והאפליקציה ניתנת להתקנה דרך הדפדפן בסביבה תומכת ללא כפתור התקנה בתוך האפליקציה.
- אחרי ביקור Online, ניתוק הרשת ורענון פותחים את ממשק האפליקציה; מוצגת הודעת Offline, ולא נשלחת קריאה ל-AI.
- לאחר חזרת הרשת אפשר לייצר בדיחה; בדיחות קודמות אינן משוחזרות לאחר רענון או פתיחה מחדש.
- `/api/jokes` אינו מוגש מ-Service Worker Cache, ומפתח API אינו נשמר ב-Cache.
- נבדקו במכשירים/אמולציות זמינים פריסת מובייל ומחשב, RTL, ניווט מקלדת, קורא מסך ובדיקות נגישות אוטומטיות; ליקויים החוסמים WCAG 2.2 AA תוקנו, ומגבלות בדיקה ידועות מדווחות.

## Milestone 5 – פריסת Production ואימות מלא

**מטרה:** לפרסם גרסה פעילה ויציבה דרך GitHub ו-Vercel ולאמת את תרחישי השימוש המאושרים.

**מה יש לממש:**
- חיבור ה-Repository ל-Vercel; הגדרת Build, פריסת Frontend ו-`/api/jokes` באותו Origin, Preview Deployments ו-Production Deployment אוטומטיים.
- הגדרת `OPENAI_API_KEY` נפרד ל-Preview ול-Production בסודות Vercel; ללא חשיפה ב-Client או ב-Git.
- בדיקות End-to-End ליצירה, טעינה, שגיאה/Retry, רשימה, העתקה, שיתוף, מחיקה, Offline, התקנה ונגישות; בדיקת HTTPS ותפקוד Function בסביבת Deployment.
- הצגת הסיכון התפעולי של Endpoint ציבורי ללא Rate Limit או מכסה יומית, כולל שימוש ב-OpenAI בתשלום; אין להוסיף הגבלת שימוש בניגוד ל-PRD.

**תוצר מצופה:** URL ציבורי פעיל של "בדיחה בקליק", עם Deployment אוטומטי מ-GitHub, יצירת בדיחות אמיתית ותמיכה ב-PWA.

**Definition of Done:**
- Preview Deployment מצליח וניתן לבדיקה; לאחר אישור המשתמש למיזוג/פרסום, Merge ל-`main` מפעיל Production Deployment אוטומטי ללא העלאה ידנית.
- ב-Production, `/api/jokes` פועל דרך HTTPS ויוצר בדיחות באמצעות `gpt-5`; כל פעולות ה-PRD עוברות בדיקות ידניות או אוטומטיות מתועדות.
- מפתחות Preview ו-Production שונים ונמצאים ב-Vercel Environment Variables בלבד; אין סודות ב-Repository, ב-Client Bundle או ב-Network Responses.
- התקנה ופתיחת Offline נבדקו בסביבה תומכת; אין Cache לתשובות AI.
- בדיקות Build/TypeScript ונגישות עוברות; כל חריגה שנותרה מפורטת במפורש לפני בקשת אישור סופי.
- אין Database, Authentication, מכסות שימוש, Rate Limiting, תפריט ניווט, מסכי אודות/הגדרות/עזרה או מועדפים.

## Development Execution Rules – הנחיות מחייבות ל-AI המבצע

1. יש לפתח את ה-Milestones **לפי הסדר** המוגדר במסמך, תוך הסתמכות על `PRD.md`, `ARCHITECTURE.md` ו-`DESIGN.md` ועל קדימות ה-PRD במקרה של סתירה.
2. בסיום **כל** Milestone יש לעצור את הפיתוח, להציג למשתמש את התוצר העובד, לפרט אילו בדיקות בוצעו ומה תוצאותיהן מול כל סעיף ב-Definition of Done, ולציין במפורש מה טרם הושלם או לא נבדק.
3. **אין להתחיל את ה-Milestone הבא ללא אישור מפורש של המשתמש.** אין לפרש שתיקה או מעבר אוטומטי כהסכמה.
4. אין להוסיף פיצ'רים או מסכים שמופיעים בתמונות בלבד אך אינם מאושרים ב-PRD. שינוי היקף מחייב אישור מפורש ועדכון המסמכים לפני המימוש.
5. אין Database בפרויקט ולכן אין צורך בסביבות Supabase או ב-Database Migrations. יש להקפיד על הפרדת Secrets בין Local Development, Preview ו-Production כמתואר ב-`ARCHITECTURE.md`.
